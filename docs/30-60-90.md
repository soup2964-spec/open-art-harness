# 30 / 60 / 90: rollout order

The order follows the platforms' constraints, from `research/08_best_practice.md` as verified in `12_verification_context.md`:
- Ad platforms only learn from value that arrives within about 7 days.
- Meta value optimization needs 100+ conversions with 5+ distinct values in 14 days.
- New Google offline setups must use the Data Manager API.

## Week 1: verify with OpenArt's own data (no changes shipped)

**Size each leak with `packages/warehouse/docs/week1-sizing-queries.md`** (BigQuery, their real event and property names):
- Meta multi-hop and return journeys (`initial_fbclid` users whose first app page view has no fbclid)
- the blocker proxy (signups with zero Amplitude events)
- webview signups
- per-arm serving cost for the default-model test
- revenue after the first purchase

**Confirm in their consoles:**
- The Google Ads signup action `rVk2CJ7Ot8EZEOSYw_Up` shows no recent conversions.
- Whether both Google Ads accounts count purchases as primary.
- Meta Events Manager: fbc coverage and match quality per event (Dataset Quality API).
- Whether a HubSpot workflow overwrites `lead_source`.
- How Stripe webhooks are consumed today.

**Set up the monitor:** run the watchdog on a schedule (it's sealed, so it's safe on production). It becomes the regression net for everything below.

## Weeks 2–6: fix the browser layer, capture attribution, start the ledger

1. **Tag fixes.** Import the `web-fixes` GTM merge pack:
   - signup trigger
   - TikTok/X/LinkedIn ids
   - `business_subscription`
   - no automatic form events
   - one page view per route change

   Ship the app patches: the full click-id list, `user_id` in the signup push, and the page-view contract. The watchdog should go green check by check.
2. **Consent.** Choose a Google-certified consent platform. Ship Consent Mode v2 defaults for EEA/UK/CH, then do a real EU-IP pass.
3. **Edge attribution.** Wrap the existing Worker with `withAttribution`, and extend `/api/user/ad-click-ids` to merge device-keyed attribution at signup.
4. **HubSpot.** Remove the hard-coded `Event/Brandweek` values, and fill the click-id and UTM fields.
5. **Warehouse v0.** Land the Stripe, Amplitude and credit-ledger sources, then build `fct_conversion_ledger` and `fct_reconciliation`. Publish the Ads-vs-Stripe reconciliation in Metabase.

## Weeks 7–12: server-side conversions, then value, then optimization

1. **Server conversions on cash value.** Turn on `conversion-service` for Google (Data Manager multi-source, same `sub_<invoiceId>`), Meta (same `purchase_<invoiceId>`), TikTok, Reddit and Microsoft, only after the matching web fix is live. Hold 3+ weeks of stable values before switching Google to value-based bidding.
2. **Predicted-profit values.** Calibrate `fct_purchase_value_score` (E[90-day gross profit | purchase], scored at purchase time) on real history: an out-of-time backtest, calibration curves, real per-model costs. Send it as the conversion value, keep cash as a secondary conversion, and move Meta lifetime value into `predicted_ltv`. Because Meta keeps the first copy it receives (the browser pixel), have `/legacy/api/stripe/checkout-session-invoice` return the same value (`profitValueMajor`) so the pixel and the server agree. The signup+24h score (`fct_predicted_profit_24h`) is for experiment and bandit readouts only, never for ad values.
3. **Prove it.** Run a holdout: a Meta conversion-lift or geo test on the switch to profit values. This matters more than any modelled result.
4. **Profit column and bandit.** Add profit per exposed user to every default-model, paywall and pricing test. Then let `bandit-allocator` manage the default-model flag weights via LaunchDarkly approvals, with a fixed holdout.
5. **Audiences.** Profit-based seed audiences and suppression of subscribers, fraud and refunds, all consent-filtered.
